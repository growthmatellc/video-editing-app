# Webinar Studio

An internal tool that runs a client's live-webinar funnel through one fixed,
ordered pipeline. Each stage produces one deliverable (blueprint, script, slides,
offer, pages, emails, SMS, objection bank, handoff, funnel spec, tracking). Most
stages are generated by an LLM using a stage-specific skill **plus the approved
output of every earlier stage as locked context**. A human reviews each stage and
approves or rejects with feedback; rejection re-runs the stage with that feedback
folded in.

The pipeline is a chain: stage N receives every approved stage before it, so the
script is consistent with the blueprint, the slides match the script, the emails
match the offer, and so on. One intake feeds the whole funnel.

This is a white-label tool. Nothing in the repo references a specific agency,
client, brand color, or account — everything operator-specific comes from
environment variables and `theme/tokens.ts`.

## Stack

- Next.js (App Router) + TypeScript + React + Tailwind CSS v4
- Drizzle ORM over any Postgres (Neon, Supabase, local) via `DATABASE_URL`
- Anthropic API (or Vercel AI Gateway), model from `LLM_MODEL`, via `lib/llm.ts`
- `.pptx` decks rendered with `pptxgenjs`, stored via `lib/storage.ts` (Vercel Blob
  or a local `/public/generated` fallback)
- Optional auth, swappable, gated behind `AUTH_ENABLED` (`lib/auth.tsx`)

## Setup

1. **Install**

   ```bash
   npm install
   ```

2. **Configure environment**

   ```bash
   cp .env.example .env
   ```

   Fill in:
   - `DATABASE_URL` — any Postgres connection string.
   - **One** LLM path: `ANTHROPIC_API_KEY` (direct) **or** `AI_GATEWAY_API_KEY`
     (Vercel AI Gateway). `LLM_MODEL` defaults to `claude-opus-4-8`.
   - `BLOB_READ_WRITE_TOKEN` — optional. Without it, generated decks are written
     to `public/generated` so local dev still produces a downloadable file.
   - `AUTH_ENABLED=false` runs single-operator with no login.

3. **Push the schema and seed the skills**

   ```bash
   npm run db:push       # create the five tables
   npm run seed:skills   # load /skills/<key>/SKILL.md into the skills table
   ```

   (`npm run db:generate` + `npm run db:migrate` is available if you prefer
   versioned migrations over `db:push`.)

4. **Run**

   ```bash
   npm run dev
   ```

## How the pipeline works

1. **Create a project** (`/new`) from a client name and a pasted intake. The intake
   is the single source of truth and is stored approved. All 14 stages are seeded.
2. **Run a stage.** The executor (`lib/skill-executor.ts`) loads the stage's skill,
   the intake, and every **approved** prior stage as locked context, then calls the
   LLM. Voice-sensitive stages run through a generate-score-retry **review gate**
   (`lib/gate.ts`) that enforces clarity, specificity, structure, and the voice
   rules, up to 3 attempts, and records a gate score.
3. **Review.** Approve to lock the stage into the context chain, or reject with
   feedback to re-run it (the prior output is archived to the `revisions` table).
4. Special stages:
   - **Brand Kit** scrapes the client's site for colors/fonts/logo (no LLM). Paste
     the URL into the feedback box if it is not in the intake.
   - **Webinar Slides** returns typed `SlideDeck` JSON, injects the approved brand
     kit, and renders a downloadable `.pptx`.

Stages: Intake → Brand Kit → Blueprint → Script → Slides → Offer Stack →
Registration Page → Ad Creative → Email Sequences → SMS Sequences →
Objection & Q&A Bank → Designer Handoff → Funnel Spec → Tracking Setup.

## Rebranding (make it theirs)

Three steps, nothing else:

1. Edit `theme/tokens.ts` — colors, fonts, app name. This is the **only** file with
   brand values; components read CSS variables wired from it.
2. Drop a logo in `/public`.
3. Set `NEXT_PUBLIC_APP_NAME`.

## The skill library

`/skills/<key>/SKILL.md` holds the generic methodology for each stage (no client
examples, no agency references). `npm run seed:skills` loads them into the `skills`
table, where `learningsMd` (overriding corrections) and `examplesMd` (quality bar)
can grow over time and are injected ahead of every generation.

## The copywriting auditor

Mapped stages (see `STAGE_ASSET_TYPE` in `lib/pipeline.ts`) are QC'd by the real
GrowthMate copywriting auditor — the deterministic Python rules from
`growthmate-knowledge/skills/copywriting/auditor/`, run as a Vercel Python
function at `/api/audit`. After each generation the auditor and the editorial
voice reviewer run together; **HARD violations automatically trigger a rewrite**
(no operator action) up to a small retry cap, then land the draft with any
residual issues flagged. YELLOW violations warn only. Unmapped stages fall back
to the lighter LLM audit in `lib/audit.ts`.

The auditor code is **vendored** into `api/audit/_vendor/` from the KB checkout:

```
npm run vendor:auditor   # re-run whenever the KB's auditor rules change
```

`vercel dev` runs the Python function locally; `ANTHROPIC_API_KEY` powers its
semantic (Claude-judge) rules and it degrades gracefully without one. The full
content rules (e.g. Tom's no-em-dash T-7) engage only when a stage emits the
auditor's expected bundle format — the relevant formatting craft is already
synced into those stages.

## Deploy

Target: Vercel. Set the same environment variables in the project settings, point
`DATABASE_URL` at a hosted Postgres, and add `BLOB_READ_WRITE_TOKEN` for deck
storage.
